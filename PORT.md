# Carried changes

The product tracks an immutable upstream-main snapshot. Compatibility changes remain patches to their actual upstream owners, not private replacements for system APIs.

## Build-time OpenSSL

`0001-vendored-build-openssl.patch` enables git2's existing vendored OpenSSL support for wezterm-version's build dependency. Cargo resolver 2 separates it from the application's dependency features; without this, native builds depend on an unavailable system OpenSSL development installation. This changes build tooling, not application trust policy. Destination: upstream wezterm-version archive-build support. Retire when upstream's build helper no longer needs this explicit selection or an equivalent shared solution covers host build dependencies.

## Archive source completeness

`0002-archive-submodules.patch` checks real required C/C++ source files instead of `.git` markers and fails with a preparation diagnostic if a source component is missing. Verified GitHub archives have no Git metadata. The regression builds the actual font dependencies with an external-git trap; unpatched build scripts invoked it four times. Destination: upstream freetype/harfbuzz build scripts. Retire when upstream supports metadata-free, complete source archives directly.

## libssh 64-bit network byte order

`patches/crates/libssh-rs-sys/libssh-rs-sys-byteorder.patch` removes unconditional Darwin HAVE_HTONLL/HAVE_NTOHLL claims. The 10.9 SDK has no such declarations; vendored libssh already provides the correct fallback macros. No substitute implementation is added. The native test characterizes those actual macros against literal network-order byte vectors in both directions, not merely a round trip. Destination: upstream libssh-rs-sys SDK-aware capability selection. Retire when the locked upstream build script detects these APIs correctly. A private crate copy is extracted from checksum-verified Cargo.lock bytes; shared registry sources are never edited.

## libssh2 source without git

`patches/crates/libssh2-sys/libssh2-sys-no-git.patch` makes libssh2-sys's build script run `git submodule update --init` only when libssh2's source is missing (`libssh2/include/libssh2.h`), not whenever `libssh2/.git` is absent. The published crate carries the complete source and no `.git`, so the script ran git on every build and ignored the result. On 10.9 without the Command Line Tools, `/usr/bin/git` is the stub that offers to install them, in a dialog. The script reads no setting that skips this step, and the path it checks is relative to the crate, so no file can be added without a private copy. `tests/libssh2_git.sh` runs the upstream and the prepared build script with a recording `git` on PATH: the upstream one calls it and the prepared one does not. Destination: upstream libssh2-sys (ssh2-rs). Retire when its build script checks for the vendored source rather than for git metadata.

## Local recipe boundaries

The currently implemented driver is native-Mavericks-only. Modern-host compilation, package identity/version resolution, updater integration and release CI are subsequent work; the absence of that work is not a release exemption. Source hashes are SHA-256s of GitHub's tarballs of the pinned commits, not upstream signatures. `scripts/pin-source-tarballs.sh` writes them only after git shows each tarball holds exactly its commit's tree, and records the parent's submodule gitlinks in `components/wezterm/gitlinks.json`. Submodule repositories are pinned under their current GitHub names (`freetype/freetype`, `pnggroup/libpng`), not the redirected names in upstream's `.gitmodules`, because GitHub names a tarball's directory after the repository's current name and the fetch requires `<name>-<commit>`.

All download/checksum/retry/extraction primitives come from shipyard. The parent and each submodule come through `fetch_pinned_source.sh`, so a 10.9 build needs no git; preparation assembles them into one tree and publishes it in a single step. Source patches (`patches/*.patch`) apply in name order through shipyard's `apply_patches.sh`, without fuzz. Each private crate's patches live in `patches/crates/<crate>/` and apply the same way to that crate's freshly extracted `.crate`; the directory's name is the crate that preparation fetches from the upstream lock and substitutes as a path override. Ownership and content manifests prevent accidental overwrites of foreign or locally modified preparation trees.

The unpatched baseline GUI link failed on Metal, UserNotifications, SSLSetSessionTicketsEnabled and CGColorCreateSRGB. The carried changes below remove those blockers without fake-success stubs or weakened certificate verification. Subsequent actual GUI acceptance, not CLI/link success, establishes the local milestone.

## Mavericks notifications

`0003-legacy-notifications.patch` adds an explicit legacy-macos feature using real NSUserNotification/NSUserNotificationCenter APIs. The package retains its modern backend as its default; this product selects the legacy feature. Both the optional binding dependency and the separate build.rs framework directive must be gated. No system API is replaced or faked. Destination: upstream wezterm-toast-notification. Retire when upstream provides an equivalent supported backend/feature boundary.

Requests run on the main operation queue, retain one delegate for process lifetime because the native center does not retain it, and use per-notification identifiers for URL activation/expiration. The pending book is pruned of dismissed delivered notifications when another request arrives; waiting requests remain tracked until delivery/error checking. A native unavailable center is an error; an accepted asynchronous request is not proof of delivery. A delayed check logs requests that never reach the center, like the modern backend's asynchronous error reporting. User notification preferences are not overridden.

Mavericks documents a userInfo property-list size below 1 KiB. The backend measures its actual binary serialization and rejects oversized URL metadata explicitly instead of provoking a native exception or dropping the URL. Title/body properties, delivery/expiration lifecycle, and restart activation are covered by thirteen native object/unit tests. The staged GUI's real banner delivery, click and three-second expiry were subsequently observed by the maintainer through its Lua toast API and actual application event loop. That GUI probe used no URL: URL opening/deduplication remains native unit coverage, not a claim of end-to-end browser interaction. For persistent notifications, activation is independent of this process's pending-delivery book. Consumed IDs have separate process-lifetime tombstones so a stored notification remains actionable after a normal restart and duplicate launch/delegate callbacks open its URL only once. The retained backend observes AppKit's genuine NSApplicationDidFinishLaunchingNotification and its NSApplicationLaunchUserNotificationKey payload; GUI frontend creation registers it before NSApplication run, even if no new toast is shown. Native tests exercise the actual Foundation broadcast/selector and genuine launch payload decoding, with only the URL-opener boundary intercepted. This is not an OS-driven cold-relaunch/browser integration claim. Modern-host behavior of the selected legacy backend remains to be validated before release.

## Optional SecureTransport session tickets

`patches/crates/security-framework/security-framework-3.7.0-runtime-tickets.patch` changes only the optional session-ticket setter and adds a private resolver module. It opens the genuine system Security framework by absolute path with RTLD_FIRST, caches the exact C-ABI function pointer or absence with OnceLock, and retains the framework reference for process lifetime. An explicit request on Mavericks returns errSecUnimplemented (-4), including an explicit false request; a real provider receives the unchanged context/Boolean and its OSStatus passes through the original error conversion. Destination: upstream security-framework. Retire when upstream provides equivalent runtime availability handling; no Recaulk API implementation has been added.

ClientBuilder defaults tickets off. The ordinary handshake, SNI, server-auth break, protocol settings and trust/hostname evaluation code are unchanged. Native tests exercise both the compiled public API and the same resolver module, with a compile-time ABI check against security-framework-sys. The packaged upstream crate omits its own unit-test certificate assets, so the external native harness avoids fetching unrelated development dependencies or adding a public test API.

The local TLS fixture uses ephemeral per-test CA/leaf files, per-connection anchors, and a loopback server linked to the already-built pinned vendored OpenSSL. It does not import identities or alter any keychain/global trust. System OpenSSL 0.9.8 only generates certificates; the actual server/client exchange is TLS 1.2. The fixture checks a trusted exchange, real wire SNI, min/max/negotiated protocol, server-auth break, untrusted-CA rejection and hostname rejection. Returning fake success for an absent setter makes two tests fail; disabling certificate verification makes both rejection tests fail. On the installed stack, the two trust failures currently surface as generic Error code 1; rejection is proved, not detailed trust-error fidelity. This measurement is recorded in the shared Recaulk queue.

## No-Metal renderer and named sRGB

`0004-no-metal-srgb.patch` selects wgpu's retained WGSL/type API without any runtime backend and reduces objc2-core-graphics to std/CGColor/CGColorSpace. This retains upstream's OpenGL renderer, not wgpu's GLES renderer; the Mavericks CGL drawable adaptation is described below. WebGpu requests fail explicitly before window/render initialization and again at the low-level WebGpu constructor. The Lua GPU enumerator uses the same unavailable diagnostic instead of entering a backendless wgpu instance (which otherwise panics). OpenGL and Software selections remain allowed. Destination: upstream product build-feature/availability handling. Retire when upstream supports an equivalent no-Metal/OpenGL-only configuration.

Cargo removed 28 optional upstream dependency identities when those defaults were disabled. Off-by-default `upstream-render-dependencies`/`upstream-graphics-dependencies` features retain the full upstream lock graph, without compiling it in the product. They are provenance-only escape hatches, not support for WebGpu; never enable them or use --all-features for this Mavericks product. The selected real GUI graph is tested to contain neither metal nor objc2-metal; all 821 original locked identities remain pinned.

The titlebar helper creates the named kCGColorSpaceSRGB via CGColorSpaceCreateWithName, then CGColorCreate with four CGFloat components, checking allocation failures and preserving CFRetained/layer ownership. No device/generic RGB fallback or exported compatibility API is introduced. Its direct objc2-core-foundation dependency uses the already-locked 0.3.2, and the patch carries the matching edge in `window`'s Cargo.lock dependency list, so the patched manifests agree with the patched lock under `cargo fetch --locked` before any crate override is applied. Native tests compare independently created named spaces with CFEqual and check transparent black, opaque white, fractional RGBA and alpha; substituting device RGB fails the identity assertion. A separate native CALayer retention characterization explicitly loads genuine QuartzCore and proves the native property retains the color after the Rust owner drops. Actual GUI startup subsequently preserved the classic Mavericks titlebar; the unavailable modern transparent-titlebar option is explicitly reported rather than silently simulated.

Shipyard's compatibility guard accepts the actual staged GUI, CLI and mux as x86_64 with SDK/minos 10.9 and no post-10.9 imports. The subsequent startup and real-app acceptance are described below.

## Native Cocoa startup and CGL presentation

`0005-cocoa-startup.patch` guards the actual effectiveAppearance, setTabbingMode:, setTitleVisibility: and setTitlebarAppearsTransparent: call sites. Missing appearance support returns the genuine supported Light appearance; unavailable cosmetic titlebar requests preserve the classic titlebar and report the limit. Available selectors still invoke their native operation. Native regressions measure all four missing methods and a supported real operation. Destination: upstream window/Cocoa availability handling. Retire when upstream supports this deployment floor equivalently.

Mavericks declares CALayer delegation as an informal NSObject category, not the later formal protocol. Window-view registration therefore adds formal conformance only when that protocol exists, preserving the real delegate selectors. Its initial backing-layer factory uses genuine CALayer instead of unconditionally requiring CAMetalLayer.

A real launch exposed an additional distinction: a successful CGL context and completed paint calls still left the terminal transparent because the view retained Core Animation layer backing after the failed EGL attempt. The native CGL constructor now detaches that backing before attaching its direct drawable, retaining the existing OpenGL renderer and Retina surface handling. A state regression reproduced wantsLayer=YES before the fix; actual owned-window images and maintainer interaction subsequently proved visible pixels. The windowless unit emits an invalid-drawable diagnostic and is not presented as visible-rendering proof.

The constructor's original native pixel-format failure also has a real negative test: request a nonexistent accelerated renderer with recovery disabled and require the original format-selection error. This tests native API/constructor rejection, not physical GPU removal or whole-GUI recovery after GPU loss. The default attribute list is unchanged. Eight Cocoa tests cover the combined availability/color/layer/negative boundaries.

macOS environment bootstrap now runs before argument parsing so the GUI's --version reports the snapshot version (`<UPSTREAM_VERSION>-mavericks.<N>`, derived from the pinned commit time) like its CLI/mux siblings. Acceptance always gives these product executions private HOME/config/runtime state, including version/help invocations; compiler-only tests retain their stable toolchain SDK/cache environment.

## Staging and local acceptance

`build/stage-app.sh` transactionally publishes an owned local app with the actual freshly built three executables, upstream icon/resources, shell integration/completion, LICENSE.md and compiled terminfo. It sets Mavericks WezTerm/dev.mavergreen.wezterm and the local source identity, and removes document associations so the private probe does not compete with installed applications. Build/stage receipts bind prepared inputs, executable hashes/modes/sizes and the staged Contents tree. Active canonical GUI sessions block rebuilding/restaging over their mapped artifacts. No installer or global trust/configuration change is involved.

`build/check-local.sh --non-gui` executes every staged executable, records real CLI PTY output, checks locked package identities, runs the real binary compatibility guard and native boundary suites. Missing artifacts, failed checks and exit77 cannot count as acceptance. LLVM ranlib is explicitly selected because Apple's developer-tool stub cannot index the vendored OpenSSL archives with this external SDK; the regression creates, indexes, links and executes an actual archive.

`--gui` launches through genuine NSWorkspace/LaunchServices, with a private Lua fixture forcing OpenGL, a private HOME and a short owned temporary symlink for native Unix-socket path limits. Those aliases point into owned evidence runs and are preserved for diagnosis. Native capture filters the exact bundle path/PID/window ID before capturing only that window. Locked desktops caused capture stalls; observer timeouts fail explicitly and leave the app alive for unlocked recovery, not another accidental launch. An unperformed GUI probe exits2/pending, never success.

The local acceptance record binds full source identity, build/stage hashes, actual renderer, owned-window images, exact maintainer-typed nonce, changed PTY dimensions, normal process/window teardown, explicit human banner click/expiry confirmation, actual Light appearance and classic-titlebar fallback. LaunchServices owns the GUI process, so no numeric GUI wait status is invented; fixture exit0, native process disappearance, Dead/Destroyed events and absence of owned-log errors are the measured shutdown evidence. Native artifact tests run sequentially because they share the canonical build/stage; the parallel runner exposed a lock conflict and one empty PTY recording, whereas the sequential fourteen-file suite passes.

A separate local checkout snapshot of the exact reviewed recipe was built with an empty target directory, reusing only checksum-verified immutable downloads and the normal registry/SDK tooling inputs, not spike/prepared/target artifacts. It rebuilt/staged all three binaries in602seconds and passed fresh non-GUI checks in241seconds. Its subsequent genuine GUI launch visibly reproduced the marker/colors/Unicode and normal teardown. This is functional reproduction, not a bit-identical-build claim or a committed-release-checkout claim.

The reviewed executable's local acceptance now passes on this Mavericks host: all12 required operations, actual Intel HD Graphics4000/OpenGL4.1 renderer, exact maintainer-typed nonce, PTY resize24x88→15x67 with visible redraw, banner click/expiry confirmation and normal teardown. Independent whole-branch review found a persistent-notification restart defect and a Python3 plist-API mismatch; both were reproduced, corrected and independently cleared before this new GUI run. Actual staging checks pass under both Mavericks Python2.7 and Python3.15.2. The stale pre-review GUI proof was explicitly rejected for the changed executable, rather than reused. The receipt is local human-assisted evidence, not a security-hardened or automated publication gate. Modern-host parity, installed package acceptance, Accessibility-free CI automation, remaining functionality and release/update infrastructure remain explicit later obligations. No package/publication readiness is implied.
